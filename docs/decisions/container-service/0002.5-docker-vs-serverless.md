# **ITD — Execution Backend Choice: Docker (vs Serverless)**

## **Summary**

After evaluating alternatives like **AWS Lambda** and **AWS Fargate**, we will use **Docker** as the execution backend for now.

* Docker provides **low-latency container startup**, **full control over runtime environment**, and **flexibility to support arbitrary languages**.
* Lambda and Fargate offer managed execution but come with trade-offs:

  * Lambda: limited language/runtime support, execution timeouts, cold start latency.
  * Fargate: slower startup per task, higher per-execution cost, additional AWS infra complexity.
* Since our goal is to build a **minimal, fast, reproducible execution service**, Docker is the most practical choice for the current stage.
* Future migration to serverless (e.g., Fargate) can be considered once system scalability needs justify it.

---

## **Definition of Done**

* Docker is established as the **only supported execution backend** in this phase.
* Documentation explains the trade-offs and why Docker was chosen.
* Clear note in repo: “Future migration path to serverless exists, but not in scope for MVP.”
